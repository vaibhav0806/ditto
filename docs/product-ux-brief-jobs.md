Ditto: product and UX brief for Jobs

Jobs,

This describes the shipped source, not the aspirational PRD. Snapshot: main at 091ebc32f03d51d6fbd0810ee9aed7a01d3f72b3, reviewed 2026-11-03. File references below are repo-relative, with line numbers at that snapshot. Browse the pinned source at https://github.com/vaibhav0806/ditto/tree/091ebc32f03d51d6fbd0810ee9aed7a01d3f72b3 . Test results are identified as recorded evidence; this brief does not claim a new live compatibility sweep.

Product in one sentence: a native macOS menu bar prototype that lets you explicitly invoke a clipboard-text suggestion at the insertion cursor, type in the host to filter it, and optionally open a separate searchable history panel. It is local string matching, not AI-generated completion. [Sources/Ditto/Keyboard.swift:34-50; Sources/Ditto/AppController.swift:193-239; Sources/DittoCore/Completion.swift:21-33]

1. Core flow after Option-Command-V

1) The fixed Carbon global hotkey invokes Ditto. Any previous session is cancelled. Secure Input produces a brief notice; an excluded foreground app causes a silent return. Ditto prunes and loads its saved history. The shortcut itself does not import another clipboard manager's history or synchronously capture the current clipboard. Capture normally runs separately every 200 ms. [Sources/Ditto/Keyboard.swift:34-50; Sources/Ditto/AppController.swift:193-203; Sources/DittoCapture/ClipboardCapture.swift:24-40,56-85]

2) Ditto asks Accessibility for the focused editable target and snapshots its text/selection. With a readable snapshot and writable selection, it creates a protected replacement session; otherwise it may create an event-tracked suffix session. A pre-existing nonempty selection is not a supported completion starting point. If no eligible session or cursor geometry is available, it shows a notice rather than automatically opening history. [Sources/Ditto/AppController.swift:204-232; Sources/Ditto/Accessibility.swift:79-125; Sources/DittoCore/Completion.swift:51-57]

3) The initial query is empty, so the newest saved eligible item is selected. Existing text before the hotkey is protected context, not automatically used as a search query. In compact mode there is ONE ghost suggestion, not a list popup. Up/Down cycles the candidates; ordinary typing goes into the host field and filters the session. Nothing is inserted by merely displaying a suggestion. [Sources/Ditto/AppController.swift:234-239,242-285,329-343; Sources/DittoCore/Completion.swift:36-57]

4) Compact presentation is a transparent, non-key, mouse-ignoring floating panel at the caret. Its width is the drawn text width, capped at 600 pt and the remaining field/display width; height comes from the caret line. Only the first line is shown, with an ellipsis for multiline content and tail truncation for long text. It selects the screen containing the converted caret point, falling back to NSScreen.main/the first screen, and clamps inside that screen's visible frame with 4 pt margins. Non-prefix matches or unsafe empty-field masking use a separate preview 5 pt below the caret line, or above if there is no room. [Sources/Ditto/Overlay.swift:15-38,71-105,128-138; Sources/DittoUI/GhostTextView.swift:110-124]

5) In an empty field, Ditto tries to cover the native placeholder visually, without writing a temporary character into the document. It prefers a matching placeholder text rectangle, samples a narrow strip of the focused app, and uses a mask only if the background passes strict uniformity checks. Known placeholder pixels can refine the baseline before masking. Typing clears the mask. Missing permission, ambiguous pixels or missing geometry can still trigger the separate preview. [Sources/Ditto/Accessibility.swift:34-40,128-138,216-232; Sources/Ditto/AppController.swift:480-546; Sources/DittoCapture/PlaceholderBackground.swift:33-72; Sources/DittoCore/PlaceholderMask.swift:16-58]

6) Tab accepts. The normal external route selects only the query typed since invocation, waits for selection acknowledgement, temporarily writes the chosen plain text to the clipboard, and posts Cmd-V. A readback must acknowledge insertion before the original clipboard is restored; newer clipboard changes are never overwritten. Timeout leaves the chosen text available for manual paste and does not replay input. Ditto's own practice editor uses NSTextView.insertText instead. The suffix fallback appends only the untyped suffix, preferring paste when it can verify the destination, otherwise using tagged Unicode events. Acceptance never adds a Return key. [Sources/Ditto/AppController.swift:374-415; Sources/Ditto/Accessibility.swift:251-310; Sources/Ditto/PasteTransaction.swift:12-51; Sources/DittoCapture/PasteboardLease.swift:12-48]

2. Autocomplete: context, filtering and unreadable fields

External targets are read through AXUIElementCreateSystemWide, AXFocusedUIElement, AXValue and AXSelectedTextRange. Eligible roles are AXTextField, AXTextArea and AXComboBox; secure-text roles are rejected. Reads have a 150 ms AX messaging timeout, and document snapshots larger than 100,000 UTF-16 units are refused. Cursor geometry comes from AX bounds-for-range, adjacent character bounds, placeholder/empty-paragraph bounds and selected text-marker fallbacks. This is a generic adapter, not an integration with each application's editor. [Sources/Ditto/Accessibility.swift:79-125,128-232]

The initial before/after-cursor strings are kept to validate the session boundary. Only characters typed AFTER invocation become the matching query. For example, invoking after an already-written word does not search that word automatically. The range-backed session checks that the original prefix/suffix remain unchanged and the caret stays at the end of the new query. [Sources/DittoCore/Completion.swift:36-57,81-101; Sources/Ditto/AppController.swift:237,310-324]

Matching is a contiguous substring search, case- and diacritic-insensitive. Start-of-item matches rank before later substrings, then newer copiedAt first, then ID for deterministic ties. An empty query is recency order. Pins do not boost ranking; there is no fuzzy, semantic, word-boundary, frequency or AI ranking. The event-tracked fallback further restricts candidates to exact case-sensitive UTF-16 prefixes, single-line/control-free content up to 4,096 UTF-16 units; its typed query is capped at 512 units. This makes the fallback less capable than normal matching. [Sources/DittoCore/Completion.swift:21-33,60-78; Sources/Ditto/AppController.swift:329-336]

If text cannot be read but an eligible field, usable caret and event-posting access exist, event tracking can still offer suffix completion. If the field itself or caret cannot be identified, there is no generic completion fallback: the user gets a notice and must open history from the menu. Missing AX permission also prevents finding an external target. [Sources/Ditto/AppController.swift:204-232; Sources/Ditto/Accessibility.swift:79-105,128-188]

Font attributes are probed near the cursor or on the placeholder; the same field's remembered style or the system font is used if they are absent. Core Text draws the ghost. Bounded local pixel matching can refine the baseline but is confidence-limited, so exact typography in every host is not established. [Sources/Ditto/Accessibility.swift:42-76; Sources/Ditto/CompletionCalibration.swift:21-68; Sources/DittoUI/GhostTextView.swift:10-71,80-140]

3. Search and the history panel

Cmd-L opens history ONLY during an active compact completion session; it is not a second global shortcut. Menu bar > Open History and the Setup button also open it. There are no bare "s" or "l" commands: those characters are ordinary query text. [Sources/DittoCore/InputPolicy.swift:23-32; Sources/Ditto/AppController.swift:165,181-182,242-259; Sources/Ditto/Setup.swift:60-63]

History becomes the key panel and focuses its own search field. The existing session query is copied into search, with the caret at its end, not selected, so typing appends to it. Host text remains unchanged while browsing. Search uses the same local substring/prefix-recency matcher. Esc discards the history-only filter and returns to the ORIGINAL session query if the original field/session is still valid; standalone history simply closes. [Sources/Ditto/AppController.swift:346-372,438-457; Sources/DittoUI/HistoryPanel.swift:297-301,430-443; Sources/DittoCore/Completion.swift:21-33]

Panel size is normally 680 x 440 pt, reduced if necessary to fit the display with 8 pt outer margins. With a caret it aligns left to the caret and prefers 8 pt below it; otherwise it goes above, then clamps. Without a caret, the screen is selected from mouse position and the panel is horizontally centered around the upper third of that screen. It is not draggable or user-resizable. [Sources/Ditto/Overlay.swift:39-68; Sources/DittoCore/HistoryPresentation.swift:5-16]

The panel has a 52 pt search header, 36 pt footer, 58%-width list and a right preview/metadata column. Rows are 34 pt high; date headings are 26 pt. Empty-query results are grouped Today/Yesterday/Earlier; filtered results are not grouped. Each row shows a source-app icon (neutral document fallback), flattened/truncated text, relative age and a pin indicator. The preview is selectable original text, capped at 5,000 characters with a truncation notice. Multiline/indented text uses a 12 pt monospaced face and 16 pt lines; ordinary text uses 13 pt system text. Source, copied time and character/line counts appear below it. It is a native popover material with rounded selection and 12 pt panel corners; Reduce Transparency switches to an opaque background. [Sources/DittoUI/HistoryPanel.swift:31-72,111-128,134-260,283-289,306-420; Sources/DittoCore/HistoryPresentation.swift:19-27]

Clicking a row selects it for preview; it does not immediately paste. Return/the primary button pastes only when the saved destination has a range-backed session; the label says "Paste to [App]". Event-tracked or unsupported destinations instead say "Copy", intentionally overwrite the system clipboard, and require a manual Cmd-V. Returning to a saved destination for paste is guarded by focus reactivation/readback. [Sources/DittoUI/HistoryPanel.swift:344-350,424-450; Sources/Ditto/AppController.swift:356-368,374-435]

4. Keyboard and hotkey inventory

Global:
- Option-Command-V: invoke/restart compact completion. Hardcoded; not customizable. A registration collision only sets a Setup status message. There is no global "open history" binding. [Sources/Ditto/Keyboard.swift:34-50; Sources/Ditto/AppController.swift:80-81,161-178]

While compact completion is active:
- Printable typing: goes to the host and filters the new session prefix.
- Backspace: edits the host/query normally; trying to delete before the session query cancels completion and passes the key through.
- Up/Down: cycle candidates, wrapping at the ends.
- Tab: accept a candidate. The current policy also accepts Shift-Tab; Shift is not excluded for that key. Without a candidate, Tab cancels and passes through.
- Cmd-L: expand history (without Shift/Option/Control).
- Esc: dismiss and preserve typed host text.
- Return/keypad Enter, Left/Right, Home/End, Page Up/Down and Forward Delete: cancel and pass through. Return DOES NOT accept the ghost and can perform the host's normal submit/newline action.
- Other Command/Option/Control combinations cancel and pass through. Shift alone is not a general cancellation modifier.
[Sources/DittoCore/InputPolicy.swift:23-32; Sources/Ditto/AppController.swift:242-285,339-343; Sources/DittoCore/Completion.swift:60-70]

History/search:
- Up/Down: move between clips, clamped at ends rather than wrapping.
- Beginning/end-of-document editing commands (normally Cmd-Up/Cmd-Down under macOS bindings): first/last result.
- Page Up/Down: move ten results.
- Return: activate the selected row; with no selection, do nothing and keep the panel open.
- Esc: return to completion or close standalone history.
- Cmd-K: open the native Actions menu.
- The Actions menu declares Cmd-C for Copy, Cmd-P for Pin/Unpin, and Cmd-Backspace for Delete. These are menu key equivalents, not separately registered global keys; normal text-editor Copy can still apply to selected search/preview text. The code's dedicated window-level shortcut handler only explicitly intercepts Cmd-K.
- Tab has no custom history-accept binding; it is left to native control focus behavior.
[Sources/DittoUI/HistoryPanel.swift:5-16,231-249,430-452; Sources/DittoCore/HistoryPresentation.swift:26-27]

Ditto's application/Edit menu declares Cmd-Q Quit, Cmd-Z Undo, Cmd-Shift-Z Redo, Cmd-X Cut, Cmd-C Copy, Cmd-V Paste and Cmd-A Select All, operating through normal responders in Ditto's own windows. Settings has no implemented Cmd-comma equivalent; status-menu entries have no key equivalents. No shortcut recorder or remapping preference is implemented. Host-app Undo behavior is separate and varies by app. [Sources/Ditto/AppController.swift:126-178; Sources/Ditto/Preferences.swift:6-62; Sources/Ditto/Keyboard.swift:49; README.md:47]

5. First run and permission/onboarding UX

Ditto is an accessory/menu-bar app with a clipboard symbol and "Ditto · Option-Command-V" tooltip, not a normal Dock app. Setup auto-opens when capture is off or Accessibility is missing; there is no first-run completion flag or multi-page wizard. Capture defaults ON, even though Setup includes a button to check/enable clipboard access. With existing AX permission and capture on, launch can remain menu-bar-only even if other permissions are missing. [Resources/Info.plist:13; Sources/Ditto/AppController.swift:53-117,153-158; Sources/Ditto/Preferences.swift:12-16; Sources/DittoCore/InputPolicy.swift:16-17]

Setup is a single checklist: (1) Accessibility for cursor/text insertion, (2) Input Monitoring for session controls, (3) local clipboard capture, plus Screen Recording for empty-field background matching. Each permission button requests/opens the relevant macOS Settings page. Clipboard access may additionally be restricted by the OS on macOS 15.4+, where the background reader respects accessBehavior and tells the user to allow background access. Accessibility/Input Monitoring grants do not by themselves grant Screen Recording. The pixel-based empty-field feature requires macOS 14+ even though the app's declared minimum is 13. [Sources/Ditto/Setup.swift:24-65; Sources/DittoCapture/ClipboardCapture.swift:43-50,69-80; Sources/DittoCapture/PlaceholderBackground.swift:35-38; Resources/Info.plist:12]

Hotkeys are taught through Setup's status, the practice editor's instructional text, the Settings footer and the README. Practice is a real editable local NSTextView with undo; it is not an interactive step-by-step tutorial. Setup offers Practice and Open History. [Sources/Ditto/Setup.swift:9,59-65; Sources/Ditto/AppController.swift:604-626; Sources/Ditto/Preferences.swift:57; README.md:22-30]

Menu bar contents: "Ditto · Capture on/paused" status; Open History; Pause Capture or Enable Capture…; Setup & Permissions…; Practice…; Settings…; Quit Ditto. The capture status reflects the preference, not a comprehensive permission/health check. Pausing capture does not disable autocomplete from already-saved history. [Sources/Ditto/AppController.swift:161-203; Sources/DittoCapture/ClipboardCapture.swift:69-85]

6. Every user preference and history-management control

- Capture copied text: persistent Boolean, default on; menu can pause it. [Sources/Ditto/Preferences.swift:6-16,32-39]
- Retention for unpinned history: 1, 7 or 30 days, default 7. Changing it prunes immediately; capture also prunes on launch, periodically and after writes. [Sources/Ditto/Preferences.swift:8,15,34-38; Sources/Ditto/AppController.swift:65,107-109; Sources/DittoCapture/ClipboardCapture.swift:65-83]
- Excluded apps: newline-separated exact bundle IDs entered manually. Defaults: com.1password.1password, com.agilebits.onepassword7, com.apple.keychainaccess. These block source capture and invocation in the foreground app; there is no application picker or automatic removal of previously stored rows from newly excluded apps. [Sources/Ditto/Preferences.swift:9,16-20,41-43; Sources/DittoCore/InputPolicy.swift:35-37; Sources/Ditto/AppController.swift:201]
- Launch at login: SMAppService main-app register/unregister toggle; an error is shown and the toggle is reset to the OS status on failure. [Sources/Ditto/Preferences.swift:27,45-53]
- Pin/unpin individual items via Actions: stored in SQLite, survives recopy, exempts them from time/count pruning; does not move them up in results. Delete removes one row without an app-level confirmation/undo flow. [Sources/Ditto/AppController.swift:463-469; Sources/DittoCore/HistoryStore.swift:53-94; Sources/DittoCore/Completion.swift:21-33]
- Clear all history: a Settings button with Cancel/Clear History confirmation. It includes pinned rows and leaves the current system clipboard alone. It is a database deletion, not forensic erasure. [Sources/Ditto/AppController.swift:593-601; Sources/DittoCore/HistoryStore.swift:84; README.md:95]

History SIZE is not a configurable preference: the hardcoded prune default keeps at most 500 unpinned items, plus pinned items with no count cap. Individual capture is limited to 1 MiB UTF-8 and rejects whitespace-only/NUL-containing text. There are no implemented appearance/font/position preferences, custom hotkeys, content-type/source search filters, folders/tags, cloud sync, export/import, snippet aliases, Show Invisibles toggle or configurable storage quota. The actual Settings form contains only the controls above. [Sources/DittoCore/HistoryStore.swift:53-55,86-94; Sources/Ditto/Preferences.swift:24-62; Sources/DittoUI/HistoryPanel.swift:134-249]

7. Supported content types and their list representation

Only PLAIN TEXT is stored. Capture reads NSPasteboard.string and the row model/schema has text, ID, timestamp, source name/bundle ID and pin status. URLs, paths, code and multiline prose are all just text; they get the same source-app icon/excerpt/age/pin row. There is no dedicated URL, code or file item renderer. [Sources/DittoCapture/ClipboardCapture.swift:77-83; Sources/DittoCore/Completion.swift:3-18; Sources/DittoCore/HistoryStore.swift:21-29; Sources/DittoUI/HistoryPanel.swift:408-420]

Rich-text formatting is NOT retained. A copy with a readable plain-text representation can become a text entry, but RTF/HTML formatting is not stored or pasted from history. Images, screenshots, file objects and arbitrary binary clipboard flavors have no history model or thumbnail/list representation. A file path copied as a string can appear, but that is not file-object support. The paste transaction's ability to temporarily snapshot/restore the CURRENT clipboard's rich/binary flavors is only clipboard preservation, not support for storing those types in history. [Sources/DittoCapture/ClipboardCapture.swift:78-80; Sources/DittoCore/HistoryStore.swift:21-29; Sources/DittoCapture/PasteboardLease.swift:18-25,33-45; README.md:47]

8. Empty/error/edge states

- Empty history: compact notice "No copied text yet · copy something to start"; history shows "Nothing copied yet" and local-storage guidance. No matches: compact notice "No clipboard matches · Esc to close"; history shows the query and a shorter-phrase/Esc suggestion. Search clears/hides preview metadata and disables primary/Actions when nothing is selected; Return does not dismiss no-results search. [Sources/Ditto/Overlay.swift:73-76; Sources/DittoUI/HistoryPanel.swift:336-354,439]
- Missing Accessibility: external autocomplete cannot start and shows Setup guidance. Standalone menu history can still offer Copy, followed by manual paste. Missing event-tap access gives a session-keyboard-controls notice; a missing caret gives a cursor-unavailable notice. [Sources/Ditto/Accessibility.swift:84-105; Sources/Ditto/AppController.swift:219-232,356-368]
- Secure Input: invocation shows "Secure Input is active · leave password entry and retry"; active completion is cancelled; capture skips changes while Secure Input is active. Secure AX field roles are separately rejected. These are detection-based protections, not proof that every custom password UI is identified. [Sources/Ditto/AppController.swift:196-199,292-295; Sources/DittoCapture/ClipboardCapture.swift:76; Sources/Ditto/Accessibility.swift:91-94]
- Password managers: recognized ConcealedType/TransientType/AutoGeneratedType/1Password pasteboard markers and the default app exclusions prevent capture. There is no content-based secret detector. History is plaintext SQLite under ~/Library/Application Support/Ditto/history.sqlite, with 0700 directory/0600 database permissions, not app-level encryption. [Sources/DittoCore/InputPolicy.swift:35-37; Sources/Ditto/Preferences.swift:16; Sources/Ditto/AppController.swift:61-64; Sources/DittoCore/HistoryStore.swift:21-31]
- A focus/app switch, screen sleep, mouse click/scroll/drag, changed surrounding text, incompatible selection or an active keyboard input-mode source can cancel the session. These guards favor preserving the host document. Copying something else also cancels it, because clipboard-change notifications call cancel. [Sources/Ditto/AppController.swift:77,83-110,289-319; Sources/Ditto/Keyboard.swift:65-79]
- Multiple monitors: layout chooses the screen containing the caret (mouse if no caret), uses visibleFrame, and samples using that screen's backing scale. Cross-display/mixed-scale behavior is not established by those calculations alone. Full-screen/Spaces: overlays are floating, but the production panel setup has no explicit canJoinAllSpaces/fullScreenAuxiliary collection behavior. Full-screen compatibility should be treated as unverified, not promised. [Sources/Ditto/Overlay.swift:22-68,93-103,128-138; Sources/DittoCapture/PlaceholderBackground.swift:40-55; docs/verification.md:110-118]
- Failed insertion: "Paste cancelled · destination changed"; no automatic retry of an uncertain mutation. History-open/storage failures open Setup or terminate after a modal database error. Some errors are weakly surfaced: pin/delete errors set model.message, but history exposes that as a footer tooltip; hotkey/capture errors can be visible only after opening Setup. [Sources/Ditto/AppController.swift:66-72,81,202-203,418-428,549-554; Sources/DittoUI/HistoryPanel.swift:348-349; Sources/Ditto/Setup.swift:59]

9. Known bugs, gaps and unfinished work

Recorded evidence, not fresh tests in this review: the newest verification entry reports a passing empty-T3 pixel comparison, full T3 completion/undo/cleanup, TextEdit empty/filled/new-line pixel comparisons and mask regressions. These supersede older T3 fallback observations further down the historical verification file. They do not prove every app works. [docs/verification.md:3-22]

Still open: the broader TextEdit multi-copy driver stops when a synthetic Cmd-A leaves an empty selection; its cause is not established as an application regression. Mid-line visible suffixes, wrapping/RTL, opaque hosts, current browsers, Ghostty/terminal, WhatsApp and spoken VoiceOver are not covered by the typography signoff. The terminal runner itself ends with "Terminal completion requires an adapter; current generic insertion path is not verified"; there is no shipped shell integration to solve it. Undo grouping also differs by route/host. [docs/verification.md:45,105-118; Tests/NativeE2E/NativeE2E.swift:775-797; Sources/Ditto/Accessibility.swift:251-269]

The separate below/above-line fallback still exists for non-prefix matches and empty fields without a valid mask. The recent empty-field fix did not remove it globally. Pixel matching has confidence/size limits and a system-font fallback; wrapped placeholders, gradients/textures, animated backgrounds and arbitrary host typography are not a finished universal rendering solution. [Sources/Ditto/Overlay.swift:78-103,128-136; Sources/Ditto/AppController.swift:514-545; Sources/DittoUI/GhostTextView.swift:10-12,56-71; README.md:32-36]

Capture is polling, so it can miss intermediate fast copies. Source attribution is best-effort: it records the frontmost app when polling observes the change. Startup initializes lastChange to the existing clipboard count, so there is no retroactive history import; new copies or Setup's explicit enable/check action are needed. Retention prunes periodically even while capture is paused. [Sources/DittoCapture/ClipboardCapture.swift:24-40,43-83]

No explicit TODO/FIXME/HACK/XXX markers were found in the production source scan. That is not feature completeness: images/files, custom shortcuts and distribution remain deferred in README, and there are structural gaps noted above. The test harness is also compiled into the app target and activated through developer command-line flags, rather than being fully separated into a test-only executable. [README.md:47; Package.swift:13-16; Sources/Ditto/AppController.swift:45,111-123]

10. Install, distribution, version and telemetry

Version is 0.1.0, build 1; minimum macOS is 13.0. The source build uses Swift tools 5.9 and Swift Package Manager with system SQLite, no third-party package declarations. The checked-in install path is developer-oriented: ./scripts/build-app.sh, then open build/Ditto.app. The script builds a release binary, constructs the bundle, and signs/verifies it using DITTO_SIGN_IDENTITY, a cached local identity or ad-hoc signing. It has no DMG/PKG, notarization, App Store or update pipeline. README explicitly calls this a non-notarized development bundle and warns that identity/path changes can affect permission continuity. [Resources/Info.plist:10-15; Package.swift:1-18; scripts/build-app.sh:1-20; README.md:7-20]

No analytics/telemetry SDK, account system, AI service or remote network client was found in the runtime source/package manifest. Matching and storage are local; the app uses OSLog for operational invocation/capture/paste diagnostics. Pixel samples and session context stay in memory in production; opt-in developer tests can save controlled fixtures locally. This is a source audit, not an independent packet-capture/privacy certification. [Package.swift:4-18; Sources/DittoCore/Completion.swift:21-33; Sources/Ditto/AppController.swift:13,194,214,523-540; Sources/DittoCapture/PlaceholderBackground.swift:34-72; Sources/Ditto/PasteTransaction.swift:6,33,43-50; README.md:85-95]

11. My three biggest UX weaknesses (judgment, based on the facts above)

A. The central interaction is conditional in ways a user cannot predict. The same shortcut can produce inline ghost text, an offset preview, a notice or silence in an excluded app. History can then switch from Paste to Copy. A user expecting "clipboard autocomplete anywhere" has to learn the host's accessibility capabilities through trial and error. I would prioritize a consistent, understandable capability/fallback contract over another round of visual polish. [Sources/Ditto/AppController.swift:193-232,356-368,480-545; Sources/Ditto/Overlay.swift:78-103,128-136]

B. Mode discovery and editing consequences are too implicit. Typing edits the real document in compact mode but edits only search in history; Esc preserves the host query; Return accepts in history but passes through to the host in compact mode. Cmd-L exists only after invocation, there is no standalone history hotkey or remapping, and compact mode shows no list/count/help for other candidates. These are learnable rules, but the UI currently makes the user remember them. I would make the transition and the accept/cancel semantics much easier to discover. [Sources/Ditto/AppController.swift:242-285,346-372,438-452; Sources/DittoCore/InputPolicy.swift:23-32; Sources/Ditto/Overlay.swift:71-105; Sources/Ditto/Keyboard.swift:49; Sources/Ditto/Preferences.swift:57]

C. First-use cost and diagnostic clarity are disproportionate for a clipboard utility. The documented path starts with a source build/local signing, then multiple macOS permissions; exclusions require typing bundle IDs. Yet the menu's "Capture on" label is just a Boolean and some actionable failures sit in Setup status or tooltips. A new user can reasonably think it is ready when it is not. I would prioritize a distributable build, a clear readiness checklist and immediate recovery guidance. The actual content scope must also be stated prominently: it is text-only, even when another clipboard tool shows images and files. [scripts/build-app.sh:1-20; Sources/Ditto/Setup.swift:24-65; Sources/Ditto/Preferences.swift:41-53; Sources/Ditto/AppController.swift:81,117,161-172,549-554; Sources/DittoUI/HistoryPanel.swift:348-349; Sources/DittoCapture/ClipboardCapture.swift:78-80]

Please review the product contract, keyboard/mode clarity and first-use flow on that factual basis. Proposed improvements above are recommendations, not implemented features.
